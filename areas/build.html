What this lens is about

I build automation for problems I have felt in production TA and HR ops: duplicated data entry, fragile handoffs, template chaos, and print queues that fail silently. The point is not demos for their own sake — it is reducing admin burden while keeping approval gates where risk lives.

I use AI daily to move faster on design, prototyping, and docs. I still own architecture, validation, and release decisions. Pattern: calculate → review → generate → approve → ship.

Universal HR HUB

Python / FastAPI · SQL · HTML/CSS/JS · Git · enterprise HR context

An internal-oriented platform to streamline HR and recruitment administrative load. Modular addons share state: vacation calculation feeds contract tokens; contracts feed a print automation queue (“Nyomtatás”), with human confirmation before documents leave the system.

Architecture & capabilities

  • Backend: Python 3.x with FastAPI; Pydantic models; REST-style request/response handling; async patterns where useful
  • Data: SQL (PostgreSQL / MySQL class designs), schema thinking
  • Template engine with {{token}} substitution; empty optional fields pruned from real document output
  • Concepts for candidate profiles, interview score aggregation, evaluation-form standardisation, funnel KPIs (source of hire, conversion, time-to-hire), department reporting
  • ATS-adjacent thinking: SuccessFactors / SmartRecruiters sync patterns via API pull/push to kill duplicate entry
  • Packaging context via PyInstaller for desktop distribution where needed
  • Design target: roughly 30–40% less admin burden per user through standardisation and fewer re-keys
